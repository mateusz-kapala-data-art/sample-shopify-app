## Directory Purposes

**`app/`:**
- Purpose: All source code for the React Router application
- Contains: Route handlers (loaders/actions), React components, server utilities, database client
- Key files: `root.tsx` (entry), `shopify.server.ts` (auth setup), `db.server.ts` (database)

**`app/routes/`:**
- Purpose: File-based routing. React Router converts each file into a route. Files define `loader()`, `action()`, and default export component.
- Contains: Route components organized by URL path pattern (e.g., `app.tsx` → `/app`, `app._index.tsx` → `/app/`)
- Pattern: File structure mirrors URL structure (flat-routes plugin)

**`prisma/`:**
- Purpose: Database schema versioning and migrations
- Contains: `schema.prisma` (single source of truth for database structure) and migration snapshots
- Generated: `node_modules/.prisma/client` (auto-generated by `prisma generate`)

**`extensions/`:**
- Purpose: Shopify theme extensions (e.g., app blocks, UI extensions). Currently empty but available for future Theme App Block functionality.
- Configured as pnpm workspace in `pnpm-workspace.yaml`
- Each extension is a separate package with its own `package.json`

**`public/`:**
- Purpose: Static assets served as-is (favicons, manifest, etc.)
- Copied to build output at root level

**`.react-router/`:**
- Purpose: Generated files by React Router build process. Do not edit manually.
- Contains: Type definitions for routes (`+routes.ts`), server build metadata
- Committed to git for build reproducibility

## Key File Locations

**Entry Points:**
- `app/root.tsx`: Root React component, renders HTML document structure
- `app/entry.server.tsx`: Server-side rendering handler, streams HTML response to browser

**Configuration:**
- `app/shopify.server.ts`: Shopify app setup, OAuth configuration, session storage
- `vite.config.ts`: Build system configuration (React Router plugin, dev server settings)

- `shopify.app.toml`: Shopify CLI configuration (API scopes, webhooks, metafield definitions)

**Core Logic:**
- `app/db.server.ts`: Prisma client singleton for database access
- `prisma/schema.prisma`: Data model (currently just Session for OAuth storage)
- `app/routes/app._index.tsx`: Demo implementation showing GraphQL mutations (product creation)

**Testing:**
- No test files detected (none configured)
- No test directory structure

**Database:**
- `prisma/schema.prisma`: Schema definition
- `prisma/migrations/`: Migration snapshots (timestamp_description format)
- Local file: `dev.sqlite` (not committed, created at runtime)

## Naming Conventions

**Files:**
- Route files: Lowercase with dots for nesting. Examples:
  - `app.tsx` → `/app`
  - `app._index.tsx` → `/app/` (index child)
  - `app.additional.tsx` → `/app/additional`
  - `webhooks.app.uninstalled.tsx` → `/webhooks/app/uninstalled`
  - `auth.login/route.tsx` → `/auth/login` (directory-based)
- Server utilities: Lowercase with `.server.ts` suffix (e.g., `db.server.ts`, `shopify.server.ts`)
- TypeScript types: Snake_case in schema, PascalCase in code (Prisma convention)

**Directories:**
- Route groups (for layout nesting): Parentheses wrapping. Example: `app/(admin)/dashboard.tsx` groups under `/app/dashboard`
- Segments: Lowercase with no special chars

**Functions:**
- Loaders/actions: Exported as named `const loader` or `const action` (React Router convention)
- Components: PascalCase default export
- Utilities: camelCase

**Types:**
- Prisma models: PascalCase (e.g., `Session`)
- Prisma field accessors: camelCase (e.g., `firstName`, `refreshToken`)

## Where to Add New Code

**New Admin Feature (Protected Route):**
- Create file: `app/routes/app.featureName.tsx`
- Structure:
  ```typescript
  import { loader, action } from "react-router";
  import { authenticate } from "../shopify.server";
  
  export const loader = async ({ request }) => {
    await authenticate.admin(request);
    // Fetch data via admin.graphql() or Prisma
    return { data };
  };
  
  export default function FeatureName() {
    // Component JSX
  }
  ```
- Test: Navigate to `/app/featureName`

**New Webhook Handler:**
- Create file: `app/routes/webhooks.topic.subtopic.tsx`
- Register in `shopify.app.toml` under `[[webhooks.subscriptions]]`
- Structure:
  ```typescript
  import { action } from "react-router";
  import { authenticate } from "../shopify.server";
  import db from "../db.server";
  
  export const action = async ({ request }) => {
    const { shop, session, topic } = await authenticate.webhook(request);
    // Process event
    return new Response();
  };
  ```

**New Database Model:**
- Edit: `prisma/schema.prisma`
- Add model (e.g., `Product`, `Shop`)
- Run: `npx prisma migrate dev --name add_product_model`
- Use in routes: `import db from "../db.server"; await db.product.findUnique(...)`

**New Utility/Helper:**
- Create: `app/utils/featureName.ts` or `app/lib/featureName.ts`
- Pattern: Export named functions or classes
- Import in routes: `import { helperFunction } from "../utils/featureName"`

**New Shopify Extension:**
- Create directory: `extensions/my-extension/`
- Configure workspace: Automatically picked up by pnpm-workspace
- Run: `npm run generate` to scaffold extension boilerplate

## Special Directories

**`.react-router/`:**
- Purpose: Generated by React Router build. Contains type stubs for type-safe routing.
- Generated: Yes (on build)
- Committed: Yes (for consistent builds)
- Edit: Never. Regenerated by `npm run typecheck` or build.

**`.shopify/`:**
- Purpose: Shopify CLI working directory (app metadata, auth tokens)
- Generated: Yes
- Committed: No (in .gitignore)

**`node_modules/`:**
- Purpose: Installed dependencies
- Generated: Yes (from package-lock.json)
- Committed: No (in .gitignore)

**`build/`:**
- Purpose: Production build output (created by `npm run build`)
- Generated: Yes
- Committed: No (in .gitignore)
- Structure: `build/server/index.js` (server entry), `build/client/` (static assets)

**`.planning/`:**
- Purpose: Project planning and codebase analysis documents
- Generated: Manually (via gsd-map-codebase)
- Committed: Yes

## Import Path Conventions

**Absolute imports configured in `vite.config.ts` and `tsconfig.json`:**
- Base URL: `.` (project root is baseUrl)
- Imports use relative paths: `import { authenticate } from "../shopify.server"`
- No path aliases configured (use relative imports)

**Module resolution order:**
1. Explicit extensions: `.ts`, `.tsx`
2. Node modules from `node_modules/`
3. Type declarations from `@types/`
